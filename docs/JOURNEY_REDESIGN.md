# 名前を届ける旅 — 操作・シナリオ・UIの再設計

## プレイの流れ

宛名を失った手紙と約束 → セナとの出会い → 案内板の記憶復元 →
整備区画でリッツを救出 → 手紙とミラの名札をつなぐ →
ミラの名前で忘鐘の装甲を弱める → 名前を港に残す／手紙に宿す選択 → 旅立ち。
市場と観測塔には、道具の作り手を取り戻す任意の記憶を配置する。

## 操作・画面

- 地面クリック／タップで移動。対象の目印・周辺一覧・案内は近づくまで。
- 到着後に「話す・調べる／進む」、またはEキーで実行。
- WASD・矢印キーで手動移動。手動入力は自動移動を中断する。
- 目印の判定は直径52px。移動中とダイアログ中は調べる操作を抑止。
- 探索・戦闘は画面高に収め、長い説明・履歴・手帳はダイアログ内で読む。
- 320/390/768/1440pxで、操作ボタン・味方HP・敵予告の見切れをブラウザ検証。

## 記憶と会話

- 2つの手がかりから、名前や意味を選択。誤答ではヒントを出し、再挑戦できる。
- 復元後に案内板の文字と灯りが戻り、ミラの記憶は忘鐘への初期崩しと共鳴に反映。
- 冒頭、仲間との出会い、修理、保管庫へ向かう場面を複数行会話で描く。
- 会話には既存の表情切替・Enter/Space/Escapeに加え、その会話内の履歴を用意。
- 終盤の2択は結果を説明してから選ぶ。報酬の差は設けず、結末の文章を変える。

## 戦闘

- 約440msのATB入力待ちを撤去。味方2行動ごとに敵が動くコマンド制。
- 敵の次の技と対象を確定し、残り味方行動数を表示する。
- ノエルの「かばう」は他の仲間への攻撃も引き受けて半減。
- セナの「記憶読解」は味方の攻撃を15%強化。リッツは崩し55の解体撃。
- 残響は共鳴100を使う追加行動。手番・敵行動数は進めず、共鳴を再生成しない。
- 敵HP・ダメージを調整。難易度や戦略の面白さは今後の実プレイヤー観察で評価する。

## セーブ

旧v1本体の形式、IndexedDB名・キーを維持。記憶の復元と最後の選択は
既存living側の任意memoryフィールドに保存。旧livingデータには初期値を補う。
JSONインポートでは記憶のID、重複、選択値も書き込み前に検証する。

## 検証

`npm test`、`npm run build`、`python tests/art-assets.py`、および
プレビュー起動後の `python tests/e2e.py`。E2Eは実際の接近・確認操作、誤答・正答、
寄り道、2戦、記憶の保存再開、結末の選択、JSON書き出しを検証する。
