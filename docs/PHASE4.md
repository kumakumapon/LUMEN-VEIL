# Phase 4 — 生きた世界と冒険

## 完成範囲
- 6エリアのデータ駆動タイルグリッド（40×20、地形タイプ、障害物タイルと従来のA*歩行判定）。生成したタイルを背景に重ねる2.5D表示。フルスクロール・広域Tiledマップは次段階。
- 港・回廊・市場・観測塔のNPCが決まった経路を往復。会話ダイアログ、タブ非表示、演出軽減時は動作停止。NPCの巡回位置は保存しない。
- 3件のクエスト：受注・進行・報酬・二重受取防止。旧序章の記録とフラグを達成条件として利用。
- 白帆の市場で装備4品を購入。所持金、購入履歴、装備画面と連動。所持金不足・重複購入は拒否。
- 状況対応AI：HP低下時の集中攻撃、防御中の相手を避ける対象選択、周期的な貫通攻撃と共鳴鐘撃の予告。元のWAITコマンド・BREAK・残響を維持。
- 既存のオリジナルキャラ絵を歩行キャラの顔に合成し、光沢・服飾・縁取りを強化。新たに生成した4人の集合画をタイトルへ組み込み、WebPで配信。
- 第3フェーズの `main` E2Eで発生したエリア遷移失敗を防ぐため、DOM側の移動選択時に古いPhaser歩行コールバックを停止。

## 保存互換性
- `web/model.mjs` の `SAVE_VERSION=1` と `web/save.mjs` の `lumen-veil-save-v1` / `slots` / `chapter-zero` を維持。
- 第3フェーズの `chapter-zero-expansion` と `PROGRESS_VERSION=1` も維持。新装備を既存の装備カタログに追加するだけで、旧装備のIDは変更しない。
- 新規 `chapter-zero-living` は `LIVING_VERSION=1`。未存在なら初期状態（200G、未受注・未購入）で再開する。
- JSONエクスポートに `living` を追加。旧v1・第3フェーズJSONは `living` がなくても読める。インポート時は旧進行・装備・新しい生活情報を**全て検証してから**同一トランザクションで書き込む。
- ゲーム本編のフラグ・HP/MP・旧セーブ形式にはタイル・NPC・クエスト・ショップの一時描画データを混ぜない。

## GitHub Pages
- Viteの `base: '/LUMEN-VEIL/'`、`dist/`、PRの検証→`main`のPagesデプロイを維持。
- 新しい画像は `public/assets/character-ensemble.webp`。画像やCSSは `%BASE_URL%` と Viteの既存処理で読み込む。

## 検証
- `npm test`：旧セーブ・装備・戦闘と新クエスト・ショップ・AI・タイルの回帰テスト。
- `npm run build`：TypeScript型チェック、Viteビルド、Pagesベースパス検証。
- Playwright：新規ゲームから序章クリア、NPC会話、依頼受注・報酬、買い物、装備、旧セーブ復元、JSON不正系、モバイル表示。
- 本番公開はPRマージ後のみ。PR内では公開しない。
